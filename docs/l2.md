# 선택적 Linux Ethernet 모드

기본 Windows 클라이언트는 Wintun 기반 L3 IPv4를 유지한다. Linux에서 소스를 전체 빌드하면 별도 `lanlink-l2` 실행 파일이 생성된다. 이 모드는 실제 커널 TAP 장치를 만들고 Ethernet 헤더와 ARP/IPv4 프레임을 보존한다. Windows/macOS용 L2 백엔드는 아직 제공하지 않는다.

~~~sh
sudo ./build/lanlink-l2 /absolute/path/to/client.conf NETWORK_ID
~~~

기존 서비스 설정의 Relay 주소, 장치 ID 파일, 인증 토큰 파일과 P2P 설정을 사용한다. 먼저 Windows 클라이언트의 네트워크 소유자가 네트워크 ID를 공유한다. Linux 장치는 위 명령으로 가입 요청을 보내며 소유자의 승인을 기다린다. 여러 Linux 장치에서 같은 네트워크 ID로 실행한다. 일반 Wintun 모드와 Ethernet 모드 사이의 게임 통신은 지원하지 않으므로 별도 네트워크를 사용한다. 프로그램은 네트워크를 자동 생성하거나 승인 절차를 생략하지 않는다.

## 동작 범위

- `lltapN`이라는 새 TAP만 생성한다. 기존 인터페이스를 재사용하거나 물리 NIC/브리지에 연결하지 않는다.
- TAP의 MAC은 멤버의 가상 IPv4에서 결정하며, Relay가 인증한 송신 IP와 내부 Ethernet/ARP/IPv4 송신 주소를 함께 검증한다.
- Ethernet 프레임을 버전 표시가 있는 내부 IPv4/UDP 패킷으로 감싼 뒤 기존 종단 간 패킷 암호화·멤버십·키 epoch·재생 방지·Direct/Relay 경로를 사용한다. 내부 포트 48042는 이 캡슐화의 식별자이며 호스트에서 별도 UDP 수신 포트를 열지 않는다. Relay 프로토콜은 변경하지 않는다.
- 현재 ARP와 가상 서브넷 안의 IPv4, 제한된 IPv4 검색 multicast/broadcast를 전달한다. IPv6, VLAN, DHCP 기반 주소 할당, STP/LLDP 등 브리지 제어 프로토콜과 외부 서브넷은 차단한다. 임의의 물리 LAN을 확장하는 투명 브리지 기능은 제공하지 않는다.
- 네트워크 하나, TAP MTU 1280을 사용한다. 캡슐화 후에도 기존 fanout 한도 1400 안에 들어간다. 검색 트래픽의 속도 제한과 중복·반사 방지는 기존 패킷 엔진을 공유한다.
- 다른 인터페이스의 IPv4 서브넷과 겹치면 설정을 거부한다. 주소가 바뀌면 프로그램을 재시작한다. 기본 경로·DNS·호스트 IP forwarding 설정을 변경하지 않는다.
- 멤버십이 사라지면 TAP을 내리고 암호화 상태를 지운다. 종료하면 비영구 TAP을 닫아 인터페이스와 연결된 경로를 제거한다. `CAP_NET_ADMIN` 또는 root 권한과 `/dev/net/tun`이 필요하다.

## 검증

`lanlink-ethernet`은 프레임 크기, 잘린 캡슐화, MAC/IP 위조, 외부 서브넷, 미지원 EtherType을 검사한다. Linux CI의 `Verify isolated Linux TAP Ethernet networking`은 root 권한으로 테스트를 실행하고, 두 자식 프로세스를 각각 새로운 네트워크 namespace로 분리한다. 두 실제 TAP 사이에서 기존 암호화 패킷 엔진을 통해 ARP와 커널 UDP 요청/응답을 전달하고, 인터페이스 충돌·서브넷 중첩 거부 및 종료 후 장치 제거를 검사한다.

이 시험의 암호화 전송 구간은 Unix datagram 채널이다. 실제 Relay/Direct QUIC 연결 검사는 기존 별도 테스트가 담당한다. 실제 게임의 그래픽 클라이언트, 다른 물리 Linux PC, Windows/macOS L2 상호 운용을 검증한 결과로 해석하지 않는다.
