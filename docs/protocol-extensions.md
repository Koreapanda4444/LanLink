# 프로토콜 확장과 이전 버전 호환성

v0.2.2의 프레임 버전 `5`, ALPN `lanlink/5`, 인증 메시지와 암호화 패킷 형식은 유지한다. 인증을 마친 새 클라이언트만 기능 협상을 요청한다.

기능 탐색은 기존 `network_list_request`의 예약 요청 ID `0xffffffff`와 `LCAP`으로 시작하는 18바이트 페이로드를 사용한다. 기존 목록 요청의 빈 페이로드와 구분된다. v0.2.2 Relay는 이 요청을 일반적인 잘못된 목록 요청으로 거부하므로 연결을 끊지 않고 기존 Relay 기능으로 돌아간다. 새 Relay는 협상하지 않는 기존 클라이언트에게 확장 메시지를 보내지 않는다.

협상에는 확장 스키마 버전, 지원하는 최소·최대 프레임 버전과 64비트 기능 집합이 포함된다. 응답은 지원 범위의 교집합만 선택한다. 범위가 맞지 않으면 확장을 활성화하지 않는다. 활성화한 기능은 인증된 연결에 귀속되고 연결이 바뀌면 초기화한다.

인증·관리·데이터 메시지는 종전처럼 버전·길이·상태를 검사한다. 아직 협상하지 않은 기능을 상대가 지원한다고 추정하거나, 알 수 없는 기능을 기본 활성화하지 않는다. 재접속·TLS/TCP 폴백도 각 연결에서 다시 협상한다.
