# 게임 연결과 검증 범위

기본 모드는 암호화된 L3 IPv4다. 게임/서버를 LanLink 가상 IPv4 또는 해당 인터페이스에 바인딩하고, 필요한 UDP/TCP 포트만 해당 프로그램에 허용한다. 전역 방화벽 해제, 물리 LAN 브리지, 포트 재지정이나 패킷 주소 재작성은 자동으로 하지 않는다. LAN 검색과 직접 IP 연결은 별도 기능이며 직접 IP가 되더라도 LAN 목록 표시를 보장하지 않는다.

| 프로파일 | 근거 | 확인한 범위 | 아직 확인하지 않은 범위 |
|---|---|---|---|
| Teeworlds 0.7.5 (`teeworlds075`) | 공식 소스와 실제 전용 서버 | Linux에서 쿠키 교환 후 서버 정보 질의, 버전·이름·응답 토큰 검증 | GUI 플레이, 실제 두 PC의 LAN 목록 표시, Windows 게임 실행 |

Teeworlds LAN 브라우저는 UDP 8303~8310으로 검색한다. 기본 서버 포트는 8303이며 사용자 지정 포트는 직접 입력한다. 검색이 안 되면 게임의 LAN 목록을 새로 고치고 호스트의 가상 IPv4:포트로 직접 접속해 본다. `lanlink-discovery-probe HOST_IPV4 PORT LOCAL_VIRTUAL_IPV4`는 선택한 단일 서버에만 최대 4초 동안 서버 정보 질의를 수행한다. 마지막 인자를 주면 가상 인터페이스의 주소로 송신 소켓을 명시적으로 바인딩한다. 포트 스캔이나 게임 설정 변경은 하지 않는다.

근거 소스는 [Teeworlds 0.7.5의 고정 커밋](https://github.com/teeworlds/teeworlds/tree/4fc25a17fef3e6c2bf4d52b0421e0d69ecaa1e79)이다. `src/engine/client/serverbrowser.cpp`의 LAN 포트 범위, `src/engine/shared/network.cpp`의 쿠키 교환, `src/mastersrv/mastersrv.h`의 질의/응답 식별자를 확인했다. CI는 이 커밋과 여기에 고정된 maps 서브모듈로 실제 서버를 빌드한다. 게임 소스·실행 파일·맵은 LanLink 저장소나 배포물에 복사하지 않는다.

새 프로파일은 확인한 버전·호스트/게스트 OS·질의와 실제 플레이의 성공/실패를 구분해서 추가한다. 확인되지 않은 게임을 지원 목록에 넣지 않는다.

멀티캐스트는 mDNS(224.0.0.251:5353), LLMNR(224.0.0.252:5355), 관리 범위 239/8로 제한한다. mDNS의 TTL 255는 변경하지 않는다. Windows는 Wintun 인터페이스의 실제 그룹 가입 목록을 사용한다. 이 목록을 제공하지 않는 어댑터는 IGMPv1/v2/v3 보고와 260초 만료를 사용하며 기존 mDNS/SSDP 기본 수신을 유지한다. IGMP 제어 메시지는 Relay로 보내지 않는다. Relay는 종단 간 암호문을 같은 승인 네트워크 안에서만 fanout하며, 그룹/송신자 필터는 복호화 후 가상 어댑터에 주입하기 전에 적용한다.

검색 트래픽은 네트워크/송신자별로 최대 32패킷/64KiB의 초기 버스트와 초당 16패킷/32KiB의 로컬 예산을 사용한다. mDNS·LLMNR·SSDP의 동일 IPv4 패킷은 100ms 안에서 합친다. 기존 Relay의 별도 fanout 예산도 유지한다. 패킷 내용을 로그나 진단에 기록하지 않는다.

`virtual_mtu`는 기본 1400이며 Windows 서비스 설정에서 576~9000으로 선택할 수 있다. 가상 어댑터의 송수신 경계에서 IPv4 길이·체크섬·조각 범위를 확인한다. 큰 유니캐스트는 IPv4 ID와 기존 offset/MF를 보존해 MTU에 맞춰 분할하며 조각 재조립은 OS에 맡긴다. 복사 비트가 없는 IPv4 옵션은 후속 조각에 복사하지 않는다. DF 패킷은 변경해서 보내지 않고 ICMP fragmentation-needed로 MTU를 알린다. 수신 측 MTU가 더 작을 때도 같은 동작을 한다. Direct/Relay 전송은 동일한 처리를 공유하고 QUIC 자체의 네트워크 경로 MTU 탐색과는 별개다.

검색 fanout은 구버전 Relay와의 호환성과 증폭 제한을 위해 최대 1400 또는 설정 MTU 중 작은 값까지만 전달한다. mDNS·LLMNR·SSDP의 조각난 패킷은 전달하지 않는다. MTU 제한을 적용해도 가상 IPv4와 네트워크 키는 변경하지 않는다.
